# Smart Irrigation Planner references

The `/irrigation` page uses the bundled district/month reference ETo dataset by default, with an optional current-day Open-Meteo model ETo path. The two modes are labelled separately; a live request never falls back to a historical normal.

| File | Use | Limits |
| --- | --- | --- |
| `simple-planner.json` | Farmer-facing growth stages, method list, calculation summary, and source links | Describes a reference estimate, not a calibrated field prescription. |
| `crop_kc.json` | FAO-56 crop coefficients plus cited FAO Water Management stage values for Millet and grouped Barley/Oats/Wheat | Standard values, not locally calibrated. Missing stage coefficients are not interpolated without stage timing. Each record identifies its source and verification scope. |
| `et0_reference.json` | Offline district and month reference evapotranspiration, 7,932 values across 661 mapped district centroids | FAO AQUASTAT / CRU CL 2.0, 1961–1990. Dataset version is in `meta.datasetVersion`. These are climate normals, not current ETo or observed rainfall; unmatched districts produce Insufficient Data. |
| `crop_water_parameters.json` | FAO-56 depletion fraction and rooting-depth references | Root-depth range is not a current-stage measurement. The calculator requires farmer-entered effective root depth. |
| `soil_reference.json` | Typical available soil water capacity by soil texture | Typical literature values; actual structure and management vary. |
| `irrigation_efficiency.json` | Published application-efficiency ranges by method | The app preserves a range; actual system performance varies. |

The offline ETo catalog already contains all twelve Saran, Bihar monthly normals. Bihar locality names `Chapra`, `Chhapra`, and `Chapara` resolve only within Bihar to the official Saran district entry. This mapping is documented in `src/data/india-district-aliases.json` and sourced to the [Saran District Administration](https://saran.nic.in/history/) and [Bihar Tourism](https://tourism.bihar.gov.in/en/destinations/saran). The displayed ETo remains the Saran district-centroid reference; it is not relabelled as a Chhapra station measurement or a district-wide average. Unsupported state/district/month keys still return Insufficient Data and never borrow a nearby district value.

The planner calculates `ETc = ET0 × Kc`. A water amount is only shown after the farmer enters measured field capacity, wilting point, current volumetric moisture, and effective root-zone depth, and the crop has a verified FAO depletion factor. It calculates TAW, measured depletion, and adjusted RAW; net refill is triggered only at/above RAW. Millimetres are converted using the saved field area and gross litres use the published method-efficiency range. The days-since-watering field is retained for reminder timing and does not stand in for a soil moisture reading.

Rainfall is stored separately in the account-scoped `RainfallObservation` table. Manual observations and weather-station readings are treated as observed entries; Open-Meteo precipitation and farmer-entered forecasts remain forecast/model scenarios and are never deducted. Historical monthly climate normals are climate context only, not rainfall for a particular field/date.

Effective rainfall uses a transparent event method: `infiltrated = gross rainfall − farmer-measured runoff/non-infiltrated loss`; `effective rainfall = min(infiltrated, measured root-zone storage to field capacity)`; any infiltrated excess is recorded as drainage. Field-capacity/current-moisture/root-depth values must be entered, and runoff/non-infiltrated loss must be measured (including an explicit zero) or effective rainfall stays unavailable. No default coefficient is invented. Events dated on or before the soil-moisture reading are not credited. A rainfall estimate is also tied to the measurement date used to compute it, so changing the soil snapshot cannot silently reuse an incompatible effective value.

The planner rolls the measured depletion forward by adding the selected ETc daily value for each calendar day after the moisture reading, then applies completed irrigation transactions and eligible observed effective-rainfall events by date. The current balance is therefore for the interval from the moisture reading to the calculation date; forecast/model rainfall is displayed as a separate scenario. The ETc rate used for elapsed days is a planning estimate based on the selected current-day or district/month reference. Paddy ETc may be displayed as crop-demand context, but rice/paddy irrigation litres remain unavailable because ponding, seepage, and percolation are not modeled.

Farmer schedules and completed watering records remain in the account-scoped `IrrigationSchedule` table. Rainfall measurements use the separate account- and crop-cycle-scoped `RainfallObservation` table. Migrations add nullable transaction IDs and create the rainfall table without updating or deleting existing irrigation records. Crop, field, soil, and crop-water stage tables remain intact.
